# ChessBot — Feuille de route complète du projet

## 0. Objectif du projet

Créer en **C** un moteur d'échecs classique fonctionnant entièrement sur CPU, puis l'intégrer à **Lichess** sous forme de bot.

Le moteur ne reposera pas sur du machine learning ou un GPU.

Objectifs principaux :

1. Comprendre le fonctionnement interne d'un moteur d'échecs.
2. Construire progressivement un moteur fonctionnel.
3. Utiliser une évaluation écrite manuellement.
4. Implémenter un algorithme de recherche classique.
5. Optimiser progressivement les performances.
6. Tester chaque composant indépendamment.
7. Implémenter une interface UCI.
8. Connecter le moteur à Lichess.
9. Mesurer son niveau réel et améliorer progressivement son Elo.

Le projet doit rester :

* gratuit ;
* compilable sur différentes machines ;
* principalement portable en C ;
* utilisable depuis VS Code ;
* stocké dans un dépôt GitHub ;
* suffisamment documenté pour pouvoir être repris par une autre IA ou un autre développeur.

# 3. Représentation actuelle du plateau

Actuellement le plateau utilise :

```c
char board[8][8];
```

Convention :

```text
Blancs = majuscules
Noirs  = minuscules
Vide   = '.'
```

Pièces :

```text
P = pion blanc
N = cavalier blanc
B = fou blanc
R = tour blanche
Q = dame blanche
K = roi blanc

p = pion noir
n = cavalier noir
b = fou noir
r = tour noire
q = dame noire
k = roi noir
```

Convention des coordonnées :

```text
board[0][0] = a8
board[0][7] = h8

board[7][0] = a1
board[7][7] = h1
```

Donc :

```text
ligne affichée = 8 - row
colonne affichée = 'a' + col
```

---

# 4. Structure Position actuelle

Actuellement :

```c
typedef struct
{
    char board[8][8];
    int sideToMove;
} Position;
```

Convention :

```text
sideToMove == 0 → Blancs
sideToMove == 1 → Noirs
```

Cette structure devra être enrichie avant la recherche.

Elle devra progressivement contenir :

```text
board
sideToMove
castling rights
en passant square
halfmove clock
```

et éventuellement d'autres informations nécessaires.

# RÈGLES DE DÉVELOPPEMENT DU PROJET

## Règle 1 — Une fonctionnalité à la fois

Ne jamais implémenter plusieurs gros systèmes simultanément.

Exemple :

```text
Cavalier
↓
tests
↓
commit
↓
Fou
↓
tests
↓
commit
```

---

## Règle 2 — Toujours tester avant de continuer

Chaque fonctionnalité doit avoir des tests.

Exemple :

```text
GenerateKnightMoves()
        ↓
tests
        ↓
résultats corrects
        ↓
Git commit
        ↓
suite
```

---

## Règle 3 — Ne pas optimiser trop tôt

Priorité :

```text
Correctness
    ↓
Tests
    ↓
Clarté
    ↓
Performance
```

Un moteur rapide mais incorrect ne sert à rien.

---

## Règle 4 — Garder le moteur indépendant de Lichess

Le moteur ne doit jamais dépendre directement de l'API Lichess.

Architecture finale :

```text
                 ┌───────────────┐
                 │    Lichess    │
                 └───────┬───────┘
                         │
                         ▼
                 ┌───────────────┐
                 │ Bot Controller│
                 └───────┬───────┘
                         │ UCI
                         ▼
                 ┌───────────────┐
                 │   ChessBot    │
                 ├───────────────┤
                 │ Position      │
                 │ MoveGen       │
                 │ Make/Undo     │
                 │ Evaluation    │
                 │ Search        │
                 │ Hashing       │
                 └───────────────┘
```
